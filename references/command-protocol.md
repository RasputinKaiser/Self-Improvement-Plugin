# SIPS command protocol — 0.7

Resolve the plugin root from current host discovery. Command examples use
`<plugin-root>` as a placeholder, not a literal path. Discover callable MCP
capabilities before invoking them; a skill listing is not runtime proof.

The active task agent uses the user's selected model. Commands do not implicitly
spawn agents, schedule campaigns, change model settings, or activate generated
repairs. Explicit delegation requests use the current host's supported roles and
limits. Keep generated SIPS improvements in the durable adaptation controller;
activation/rollback requires the exact reviewed candidate. Ordinary user-requested
project work retains its explicitly authorized scope.

Distinguish observation, mechanism hypothesis, proposed intervention, executed
evaluation, review, and activation. Preserve raw evidence and dirty checkout
changes. Record declared assumptions, invalidation conditions, counterexamples,
and source identities. Research-method results are advisory models, not passing
evaluation receipts. A literature analogy is not an empirical result.

Report source, installed cache, fresh process, and current-task callability
separately. Save receipts in durable local paths, and update state.yaml and the
ledger after writes. Pure status/search/analysis requests remain read-only.
See research-methods.md for executable methods, request shapes, and references.
